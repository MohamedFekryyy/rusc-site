# Patches on top of Cal.diy

`.github/workflows/cal-image.yml` applies every `*.patch` here (with `git apply`, in name order) to the pinned `calcom/cal.diy` commit before building the image. The image tag includes a hash of these files, so changing a patch builds and deploys a new image.

| Patch | Why |
|---|---|
| `booker-lang.patch` | The booker follows the site's page language, not the visitor's browser. The site passes `?lang=fr` or `?lang=en` (`components/BookingEmbed.tsx`): the booking pages load that locale's labels, the class title and description use that language (French is the source, English comes from `EventTypeTranslation`), and the French booker opens with 24-hour times (the 12h/24h toggle still works for the visit). Files: `apps/web/app/(booking-page-wrapper)/[user]/[type]/{,embed/}page.tsx`, `apps/web/modules/bookings/components/EventMeta.tsx`, `packages/features/bookings/lib/timePreferences.ts`. |
| `embed-success.patch` | Embedded, the booker stays where it is after a booking: the site shows its own message and takes the place to the cart. The `bookingSuccessful` event also carries `booking.ruscPlaces`, the number of places asked for (see `seats-count.patch`). File: `apps/web/modules/bookings/hooks/useBookings.ts`. |
| `hide-branding.patch` | No "try it for free" / Cal.diy branding on the booking success page, and no "by continuing you agree to Cal.diy's Terms and Privacy Policy" line in the booking form (it linked to cal.com; the site's booking pages link the studio's own terms). Files: `apps/web/modules/bookings/views/bookings-single-view.getServerSideProps.tsx`, `apps/web/modules/bookings/components/BookEventForm/BookEventForm.tsx`. |
| `late-booking.patch` | People can book a class until 30 minutes after it starts (owner's request, 2026-09-24). Stock Cal.diy refuses any time before now, and its minimum booking notice (default 2 hours) can't go below 0. With the patch, a **negative** notice is a grace period: the classes have `minimumBookingNotice = -30`. Slots already start from "now + notice", so only the in-the-past guard needed the grace. File: `packages/lib/isOutOfBounds.tsx`. |
| `parallel-classes.patch` | rūsc's classes run side by side under one host (Mondays at 16:00: wheel throwing, hand-building and raw-glaze decoration), each with its own seats. Stock Cal.diy counts a booking of any event type as busy time for the host, so one class would block the others. With the patch, only bookings of the same event type count; seats still fill a class up. File: `packages/features/busyTimes/services/getBusyTimes.ts`. |
| `rusc-wording.patch` | The confirmation screen said "This meeting is scheduled" and "calendar invitation" (Cal.diy's default). rūsc is a studio with classes, not meetings: the patch changes the EN and FR strings to "Your class is booked / Votre cours est réservé" and drops the calendar-invitation wording. It also says "7 places disponibles / 7 places available" instead of "Places" / "Seats". File: `packages/i18n/locales/{en,fr}/common.json`. |
| `seats-count.patch` | The guests field becomes a "number of places" selector (− 1 +). Cal books **one** place, the booker's: the mapper drops the selector's entries before the request, and `embed-success.patch` passes the count to the site, which adds the other places through rūsc admin (`/api/places`), checked against the class's capacity. The cart's + and − use the same route. File: `apps/web/modules/form-builder/components/Components.tsx`, `packages/features/bookings/lib/client/booking-event-form/booking-to-mutation-input-mapper.tsx`, and the two strings in `packages/i18n/locales/{en,fr}/common.json`. |
| `seats-pending.patch` | Classes are booked PENDING until paid (`requiresConfirmation`), their places held meanwhile (rūsc admin frees unpaid ones after 30 minutes). Stock Cal.diy only adds a second person to an ACCEPTED booking of the same slot, so the second person in an unpaid class got "already booked"; and it only counted ACCEPTED bookings for the places left, so held places didn't show as taken and a class held full still looked open. Both also count PENDING. Files: `packages/features/bookings/lib/handleSeats/handleSeats.ts`, `packages/features/bookings/repositories/BookingRepository.ts` (`findAcceptedBookingByEventTypeId`, only used for the places left). |

When updating `CAL_DIY_REF`, check that each patch still applies (the build fails if not) and still makes sense.

Keep the booking/confirmation translations together in `rusc-wording.patch`, generated with normal diff context against the pinned source. A separate zero-context wording patch cannot be applied by the workflow's plain `git apply` and may conflict with this patch.

**Check patches before pushing.** A push that touches this folder starts a 13-minute image build, and a patch that doesn't apply fails it. Download the touched files at the pinned commit into a scratch git repo (`raw.githubusercontent.com/calcom/cal.diy/<CAL_DIY_REF>/<path>`), commit them, then `git apply` every patch in name order and validate the JSON files. Two patches touch the locale files (`rusc-wording`, then `seats-count`): regenerate the later one against the earlier one's result.
